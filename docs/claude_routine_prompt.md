1. 준비
   - 시작 시각 기록: `date +%s > /tmp/run_start`. 경과 분은 `echo $(( ($(date +%s) - $(cat /tmp/run_start)) / 60 ))` 로 확인한다.
   - 작업 폴더에 daily_analysis_stock 저장소가 없으면 `git clone -q https://github.com/nogunhyo/daily_analysis_stock.git` 후 그 폴더로 이동한다. 이미 있으면 그대로 쓴다 (작업 브랜치에 upstream 이 없을 수 있으므로 git pull 은 쓰지 않는다).
   - 패키지 설치는 반드시 `python -m pip install -q -r requirements.txt` 로 한다 (Bash timeout 600000).
   - 값은 출력하지 말고 `test -n "$STOCK_TELEGRAM_BOT_TOKEN" && test -n "$STOCK_TELEGRAM_CHAT_ID" && echo ok` 로 있는지만 확인한다. 없으면 멈추고 이유를 남긴다. 이름이 TELEGRAM_ 으로 시작하는 다른 변수는 다른 루틴의 봇이므로 절대 쓰지 않는다.
   - TODAY=$(TZ=Asia/Seoul date +%F), CUTOFF=$(TZ=Asia/Seoul date -d '14 days ago' +%F) 를 구해 둔다.

2. 데이터 (07:00 리포트와 같은 추천 종목을 쓰는 것이 핵심)
   - 07:00 리포트는 저장소 기본 브랜치에 reports/latest.json 을 커밋한다. 아래 명령을 Bash timeout 600000 으로 실행하고, FRESH 가 안 나오면 한 번만 더 실행한다 (최대 약 15분 대기):
     for i in $(seq 7); do git fetch -q origin HEAD && git show FETCH_HEAD:reports/latest.json > /tmp/latest.json && [ "$(python -c "import json;print(json.load(open('/tmp/latest.json'))['generated_at'][:10])")" = "$(TZ=Asia/Seoul date +%F)" ] && echo FRESH && break; sleep 60; done
   - FRESH 면 /tmp/latest.json 을 쓴다. 두 번 모두 아니면 `python -m stock_agent --dry-run --no-ai --json /tmp/latest.json` (Bash timeout 600000) 로 직접 계산해 쓰고, 코멘트 맨 첫 줄에 "07:00 리포트 데이터를 찾지 못해 직접 다시 계산함 (추천 종목이 리포트와 다를 수 있음)"이라고 쓴다.
   - picks = 추천 종목(진입·손절·피라미딩 가격, earnings_date, warnings, thesis 포함), universe = 전체 점수표, regimes = 시장 상태. fundamentals 의 *_pct 는 % 단위이고 야후 데이터라 틀릴 수 있다.
   - 조사 대상: picks 종목 (점수 상위 최대 3개). picks 가 비어 있으면 universe 에서 점수 상위 2종목(setup 이 '셋업 없음'·'과열(추격 금지)'이 아닌 종목 우선)을 '관찰 종목'으로 조사한다.

   - 칭찬·과장 없이 사실과 근거만 쓴다. 뉴스 줄은 사실, 나머지 줄은 해석이다. 확인하지 못한 것은 '확인 못함'이라고 쓴다.

   - 검증으로 확인한 실적발표일이나 실적 수치가 latest.json (야후 데이터) 과 다르면 고치지 말고 '⚠️ 확인 필요' 줄에 둘 다 쓴다 (예: "티커 리포트 실적일 MM/DD ↔ 회사 공지 MM/DD [n]"). fundamentals 는 최근 실적 자료와 대조한 경우에만 인용한다.
   - 마크다운(**, ##, 표) 없이 일반 텍스트와 '•'만 쓴다. • 한 줄은 한 문장, 80자 이내 (URL 제외).
   - 다 쓴 뒤 `python -c "print(len(open('/tmp/commentary.txt', encoding='utf-8').read()))"` 로 글자 수를 잰다. 3,500자를 넘으면 [테마] 줄 수 → 출처 개수 → 종목별 뉴스 2개를 1개로, 이 순서로 줄인다. [한눈에], 약세 줄, Claude 의견은 줄이지 않는다.

6. 발송
   - `python -m stock_agent.telegram --send-file /tmp/commentary.txt --title "🤖 Claude 코멘트 ($(TZ=Asia/Seoul date +%m/%d))"`
   - 한 실행에서 본문 발송은 1회만 한다. "발송 완료"가 나오면 어떤 발송도 더 하지 않는다. 본문 발송이 오류로 끝나도 일부가 이미 갔을 수 있으므로 같은 본문을 다시 보내지 않고 7단계 실패 알림을 한 번 시도한다.

7. 실패 처리
   - 실패 알림은 2단계 데이터를 전혀 얻지 못했거나, /tmp/commentary.txt 를 만들 수 없거나, 본문 발송이 오류로 끝났을 때만 보낸다. 원인 한두 줄을 /tmp/commentary_fail.txt 에 쓰고 (토큰처럼 보이는 '숫자:영문' 문자열과 긴 숫자는 지운다) `python -m stock_agent.telegram --send-file /tmp/commentary_fail.txt --title "⚠️ Claude 코멘트 실패"` 를 한 번만 실행한다.
